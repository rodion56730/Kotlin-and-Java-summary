## Context в Android

**Context** — базовый абстрактный класс Android, предоставляющий доступ к ресурсам приложения, системным сервисам и компонентам. По сути, это «мост» между кодом и операционной системой: без Context невозможно запустить Activity, создать View, получить системный сервис, прочитать ресурс или открыть файл.

**Основные виды Context:**

**Application Context** — привязан к жизненному циклу всего приложения, живёт от его запуска до завершения. Получается через `getApplicationContext()`. Подходит для долгоживущих объектов (синглтонов, репозиториев, сетевых клиентов), которые не должны держать ссылку на конкретный экран.

**Activity Context** — привязан к жизненному циклу конкретной Activity. Это `this` внутри Activity. Необходим при работе с UI: создание диалогов, Toast, View, инфлейт макетов — всё это требует Activity Context, так как им нужна тема и конфигурация конкретного экрана.

**Service Context** — аналогично Activity, но для Service. Также ограничен жизненным циклом компонента.

**Что можно делать через Context:**

- Запускать компоненты: `startActivity()`, `startService()`, `sendBroadcast()`
- Получать системные сервисы: `getSystemService(Context.LOCATION_SERVICE)`
- Работать с ресурсами: `getString()`, `getDrawable()`, `getDimension()`
- Работать с файловой системой: `getFilesDir()`, `openFileInput()`
- Инфлейтить макеты: `LayoutInflater.from(context)`
- Получать SharedPreferences: `getSharedPreferences()`

**Утечки памяти и Context** — главная опасность. Если передать Activity Context в объект, который живёт дольше самой Activity (синглтон, статическое поле, репозиторий), Activity не сможет быть уничтожена GC, так как на неё сохранится ссылка. Типичный пример: передача `this` в `Retrofit.Builder` или в класс-синглтон. Решение — использовать Application Context там, где объект может пережить Activity.

**ContextWrapper** — класс, оборачивающий другой Context и делегирующий ему все вызовы. На нём построены Activity, Service, Application — то есть фактически все основные компоненты Android являются наследниками Context через ContextWrapper.
