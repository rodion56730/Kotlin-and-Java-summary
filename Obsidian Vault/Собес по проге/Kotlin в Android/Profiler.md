## Android Profiler

Android Profiler — инструмент в Android Studio для анализа производительности приложения в реальном времени. Находится во вкладке **View → Tool Windows → Profiler**. Подключается к запущенному процессу на устройстве или эмуляторе. Состоит из четырёх независимых профайлеров: CPU, Memory, Network, Energy.

---

## CPU Profiler

Показывает загрузку процессора и помогает найти медленные методы, зависания UI и лишнюю работу в главном потоке.

**Режимы записи:**

- **Callstack Sample** — периодически снимает стек вызовов (низкие накладные расходы, подходит для общего анализа)
- **Trace Java Methods** — инструментирует каждый вход/выход метода (точные данные, но замедляет приложение)
- **Trace System Calls** — показывает системные вызовы ядра, полезен для анализа I/O и синхронизации
- **Profileable** — облегчённый режим для release-сборок без отладочного кода

**Что искать:**

- Длинные вызовы на **Main Thread** — всё, что занимает больше 16 мс, вызывает пропуск кадра (jank)
- Методы с большим **Self Time** (время без учёта дочерних вызовов) — именно они тормозят
- Вкладка **Flame Chart** — наглядно показывает стек вызовов: широкие полосы = много времени
- Вкладка **Top Down / Bottom Up** — сортировка методов по времени выполнения

**Типичные проблемы:** inflate в `onBindViewHolder`, тяжёлые операции в `onCreate`, синхронные запросы к БД или файлам на Main Thread.

## Memory Profiler

Показывает потребление памяти в реальном времени и помогает найти утечки памяти и избыточное выделение объектов.

**Основной график** отображает: общую выделенную память, количество объектов (Objects), количество классов. Резкий рост с последующим падением (GC) — признак избыточного выделения объектов в цикле.

**Heap Dump** — снимок всех объектов в памяти в конкретный момент. Как анализировать:

1. Нажать **Dump Java Heap**
2. Отсортировать по **Retained Size** (сколько памяти освободится при удалении объекта)
3. Найти подозрительные объекты (Activity, Fragment, Bitmap, Context) — их не должно быть много экземпляров
4. Посмотреть **References** — кто держит ссылку на подозрительный объект

**Как поймать утечку Activity:**

1. Открыть экран → закрыть экран → нажать **Force GC** (кнопка в профайлере)
2. Сделать Heap Dump
3. Найти класс Activity в списке — если экземпляр остался, это утечка
4. Смотреть в **Instance Details** → **References** — найти цепочку, кто удерживает

**Record Allocations** — записывает каждое выделение объекта с трассировкой стека. Помогает найти место в коде, где создаётся слишком много временных объектов (например, в методах, вызываемых при скролле).

## Network Profiler

Показывает все HTTP-запросы приложения: URL, метод, размер запроса/ответа, время выполнения, статус-код. Работает автоматически с OkHttp/Retrofit без дополнительной настройки.

**Что искать:**

- Запросы, которые выполняются последовательно там, где можно параллельно (`zip` в RxJava)
- Слишком большие ответы (лишние поля, нет пагинации)
- Повторные запросы одних и тех же данных (нет кеширования)
- Долгое время ответа — нажать на запрос и посмотреть вкладку **Timeline** (время DNS, соединения, ответа)

## Energy Profiler

Показывает примерное потребление энергии и системные события: Wake Lock, Job Scheduler, будильники (Alarm), Location-запросы. Помогает найти компоненты, которые не дают устройству уснуть.

---

## System Trace (perfetto)

Более глубокий инструмент, доступный через **CPU Profiler → Trace System Calls** или отдельно через Perfetto. Показывает работу на уровне системы: рендеринг кадров, Choreographer, работу потоков, Binder-вызовы (IPC).

**Как читать кадры:** на дорожке **Frames** зелёные кадры = ≤16 мс (60 fps), жёлтые = небольшой jank, красные = тяжёлый пропуск кадра. Нажать на красный кадр → посмотреть, какой метод занял время на Main Thread или RenderThread.

## Практический алгоритм отладки

|Симптом|Инструмент|Что искать|
|---|---|---|
|Лагает скролл / анимация|CPU Profiler → Flame Chart|Долгие методы на Main Thread|
|Растёт память, OOM|Memory Profiler → Heap Dump|Retained Size, утечки Activity|
|Много мусора / GC|Memory → Record Allocations|Объекты, создаваемые в цикле|
|Медленная загрузка данных|Network Profiler|Последовательные запросы, размер|
|Быстро садится батарея|Energy Profiler|Wake Lock, фоновые задачи|
|Jank на конкретном экране|System Trace|Красные кадры, Choreographer|

**Главное правило:** профилировать на реальном устройстве в **release-сборке** (или `profileable`-режиме) — эмулятор и debug-сборка дают искажённые результаты из-за дополнительных проверок и отсутствия AOT-компиляции.
